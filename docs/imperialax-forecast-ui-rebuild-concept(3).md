# ImperialAX Laminate Forecast — 처음부터 새로 만든다면 (구조 재설계안)

이 문서는 `imperialax-forecast-ui-redesign.md`(기존 화면 위에 sticky/아코디언을 얹는 점진적 개선안)와는 별개로, 화면을 처음부터 다시 설계한다면 어떤 구조를 택할지 정리한 문서다. 기존 구현을 고치는 패치가 아니라 정보 구조(IA) 자체를 바꾸는 안이다.

## 1. 문제의 근본 원인

기존 화면은 빠르게 후보를 스크리닝하려는 사용자와, 근거를 깊게 검증하려는 사용자를 같은 화면·같은 스크롤 흐름에 몰아넣는다. 요약, 곡선, XAI, 디자인 스페이스, 케이스 리스크, 히스토리가 전부 한 페이지에 순서대로 쌓여 있어 페이지 길이가 사용자 목적과 무관하게 항상 최대치로 길어진다. 제품의 핵심 가치(랜딩 페이지 기준: "많은 조합을 빠르게 훑고 유망한 후보만 깊게 검증")를 화면 구조가 뒷받침하지 못하고 있다.

## 2. 설계 원칙

1. **스크리닝과 딥다이브를 명시적으로 분리한다.** 같은 화면 안에 모든 정보를 항상 노출하지 않는다.
2. **쌓지 않고 교체한다.** 아코디언으로 세로로 쌓는 대신 탭으로 콘텐츠를 교체해 페이지 길이를 일정하게 유지한다.
3. **비교가 1급 기능이다.** 여러 실행 결과를 나란히 비교하는 것이 이 도구의 핵심 가치이므로, 비교 테이블을 사이드 카드가 아니라 정식 섹션으로 승격한다.
4. **상태를 먼저 설계한다.** 빈 상태 / 로딩 / 결과 있음 / 에러를 컴포넌트 설계 전에 확정해 상태 불일치(예: 결과가 있는데도 "실행 전" 경고가 뜨는 문제)를 원천 차단한다.

## 3. 전체 레이아웃

```
헤더 (제품명, 상태 뱃지, 언어 전환)
─────────────────────────────────────────
모드 토글: [빠른 스크리닝] [딥 다이브]           현재 입력 요약(Case 2 · θ 30/-30)
─────────────────────────────────────────
┌───────────┬─────────────────────────────┐
│ 입력 패널   │  탭바: 요약 | 곡선 | XAI | 디자인 스페이스 │
│ (sticky)   │  ─────────────────────────  │
│            │  탭 콘텐츠 영역 (교체 방식)      │
│ - Theta1/2 │                             │
│ - Case     │                             │
│ - 패널 치수  │                             │
│ - 실행 버튼  │                             │
│ - 3D 미리보기(축소) │                       │
└───────────┴─────────────────────────────┘
─────────────────────────────────────────
실행 이력 비교 테이블 (Case / θ / Type / Pt / 신뢰도, 정렬 가능)
```

3D 프리뷰는 기존처럼 별도의 넓은 컬럼을 차지하지 않고 입력 패널 안에 축소된 보조 요소로 둔다(필요 시 클릭해서 확대).

## 4. 컴포넌트 스펙

### 4-1. 모드 토글
- `빠른 스크리닝`(기본값): 탭 중 "요약"만 노출, 나머지 탭은 숨김 또는 비활성.
- `딥 다이브`: 모든 탭(요약/곡선/XAI/디자인 스페이스) 노출.
- 토글 상태는 세션 동안 유지(로컬 상태로 충분, 서버 저장 불필요).

모드 토글은 탭이 아니라 "둘 중 하나만 선택되는 설정값"이므로 `role="tab"`을 쓰지 않는다. `role="radiogroup"` + `role="radio"`(세그먼트 컨트롤 패턴)를 사용한다.

```html
<div class="mode-toggle" role="radiogroup" aria-label="분석 모드">
  <button role="radio" aria-checked="true" data-mode="quick">빠른 스크리닝</button>
  <button role="radio" aria-checked="false" data-mode="deep">딥 다이브</button>
</div>
```

### 4-2. 입력 패널 (sticky)
- `position: sticky; top: <header 높이>; align-self: start;`
- 부모 grid는 `align-items: start` 필수.
- 요소 수를 최소화: Theta1, Theta2, Case, 패널 치수, 실행 버튼. 3D 미리보기는 접이식(`<details>`)으로 기본 접힘.

### 4-3. 탭 기반 결과 영역
- 탭: 요약(기본 활성) / 곡선 / XAI / 디자인 스페이스.
- 네이티브 탭 패턴 권장: `role="tablist"` + `role="tab"` + `role="tabpanel"`, 화살표 키로 탭 간 이동, `aria-selected` 동기화.
- 탭 전환 시 스크롤 위치를 유지(페이지 최상단으로 튀지 않게).
- 요약 탭 값은 5개(Type, 확률, Predicted Pt, 최대 변위, 신뢰도)이며, 다음 규칙으로 카드 4개로 그룹화한다: ① Type + 확률을 하나의 대표(hero) 카드로 묶고, ② Predicted Pt, ③ 최대 변위, ④ 신뢰도는 각각 별도 metric 카드로 분리한다.

```html
<div class="tabbar" role="tablist" aria-label="예측 결과 보기">
  <button role="tab" aria-selected="true" aria-controls="panel-summary">요약</button>
  <button role="tab" aria-selected="false" aria-controls="panel-curve">곡선</button>
  <button role="tab" aria-selected="false" aria-controls="panel-xai">XAI</button>
  <button role="tab" aria-selected="false" aria-controls="panel-space">디자인 스페이스</button>
</div>
<div id="panel-summary" role="tabpanel">...</div>
<div id="panel-curve" role="tabpanel" hidden>...</div>
<div id="panel-xai" role="tabpanel" hidden>...</div>
<div id="panel-space" role="tabpanel" hidden>...</div>
```

### 4-4. 실행 이력 비교 테이블
- 컬럼: Case, θ1/θ2, Type, Pt, 신뢰도 (필요 시 최대 하중·최대 변위 추가).
- 정렬 가능(컬럼 헤더 클릭), 최근 실행이 최상단, 현재 선택된 입력과 일치하는 행 하이라이트.
- 행 클릭 시 해당 입력값을 입력 패널에 다시 채워 넣음("재사용" 동작 — 기존 화면의 "Tap a card to reuse its setup"를 표 형태로 승격).
- 향후 확장: 체크박스로 2~3개 행을 선택해 곡선을 오버레이 비교하는 기능(이번 스펙 범위 밖, 백로그로 기록).

## 5. 상태 설계

| 상태 | 조건 | 표시 |
|---|---|---|
| 빈 상태 | 아직 한 번도 실행 안 함 | "입력값을 설정하고 예측을 실행하세요" + 입력 패널 강조 |
| 로딩 | 실행 버튼 클릭 직후 ~ 응답 전 | 요약 탭 영역에 스켈레톤/스피너, 실행 버튼 비활성화(라벨은 유지, `disabledReason` 툴팁으로 이유 설명) |
| 결과 있음 | 응답 완료 | 요약 탭 자동 활성화, 하단 비교 테이블에 새 행 추가 |
| 에러 | API 실패, 입력값 범위 초과 | 입력 패널 하단에 인라인 에러 메시지. 페이지 하단에 상태와 무관하게 고정 노출되는 배너 방식은 지양 (기존 화면에서 발견된 "결과가 있는데도 경고가 뜨는" 문제의 원인) |

## 6. 반응형

- 데스크톱(1024px 이상): 입력 패널 + 탭 워크스페이스 2열 유지.
- 태블릿 이하(1024px 미만): sticky 해제, 입력 패널을 상단 카드로 전환. 탭바는 가로 스크롤 가능한 pill 형태로 축소.
- 경계값은 `imperialax-forecast-ui-redesign.md`와 통일: 1024px을 기준으로 "이상=데스크톱 / 미만=모바일"로 겹치지 않게 정의한다.
- 비교 테이블은 좁은 화면에서 카드 리스트로 전환(테이블 가로 스크롤보다 우선 고려).

## 7. 접근성 체크리스트

- 탭바: 키보드 좌우 화살표로 탭 이동, `Home`/`End`로 처음/끝 탭 이동, `aria-selected` 동기화.
- 모드 토글: `role="radiogroup"`/`role="radio"` 패턴 사용. 좌우 화살표로 옵션 이동, `aria-checked` 동기화. `role="tab"`은 콘텐츠 패널 전환용이므로 사용하지 않는다.
- 비교 테이블 정렬 버튼에 `aria-sort` 반영.
- 색상만으로 상태를 구분하지 않기(신뢰도 "높음/보통/낮음" 같은 텍스트 라벨 항상 병기 — 기존 화면은 이미 잘 하고 있음, 유지).

## 8. 기존 리디자인 문서와의 관계

`imperialax-forecast-ui-redesign.md`는 현재 구현 위에 최소 변경(sticky + 아코디언)으로 적용 가능한 단기 개선안이다. 이 문서는 정보 구조 자체를 바꾸는 중장기안이다. 리소스가 제한적이면 먼저 redesign.md의 sticky/아코디언 안을 적용하고, 이후 이 문서의 탭 기반 구조 + 비교 테이블 승격으로 단계적으로 이전하는 것을 권장한다.

## 9. 비주얼 스타일 가이드

`index-rebuild.ko.html` 구현 검토 결과, 구조(모드 토글/탭/히어로 카드/비교 테이블)는 스펙대로 반영됐으나 시각 스타일이 플랫·미니멀 톤과 다르게 나왔다(히어로 카드 그라디언트, 상단 바 진한 검정 배경, 굵은 대형 타이포, 영문 라벨 전체 대문자 등). 아래 규칙으로 정리한다.

### 타이포그래피
- 폰트: 시스템 산세리프 스택 `-apple-system, "Segoe UI", Inter, sans-serif`.
- font-weight는 400(본문)과 500(강조/제목) 두 가지만 사용. 600~800 웨이트 금지.
- 크기: h1 22px / h2 18px / h3 16px, 본문 16px · line-height 1.7. 히어로 카드의 "Type 2" 같은 큰 숫자/라벨도 32px 선을 넘지 않는다.
- 대소문자: 영문 eyebrow 라벨(FORECAST SETUP, PREDICTED PT 등) 전체 대문자 금지. sentence case로 통일.

### 색·배경
- 그라디언트 금지: 히어로 카드의 남색 그라디언트 배경 제거, 흰색/연회색 플랫 배경으로 교체.
- 진한 단색 블록 지양: 상단 모드 토글 바의 검은 배경 제거, 흰 배경 + 0.5px 헤어라인 보더로 대체.
- 강조는 색이 아니라 타이포그래피 크기·굵기 차이로 표현.
- 그림자(box-shadow) 대신 0.5px 보더 사용.

### 배지·상태 색상
- 신뢰도 배지("높음·95%" 등)는 채도 높은 배경 + 흰 글씨 대신, 옅은 tint 배경(예: 연초록) + 동일 색상 계열의 진한 텍스트(진초록) 조합 사용.
- 배지 텍스트 대비 기준: 배경이 밝은 tint면 텍스트는 같은 색상군의 어두운 단계여야 한다(임의의 검정/회색 금지).

### 카드·보더·라운드
- 카드 radius 12px, 버튼/인풋 등 컨트롤 radius 8px로 통일.
- 카드 배경은 흰색, 보더 0.5px, 패딩 1rem~1.25rem.

### 버튼 위계
- 화면당 강조(accent, 진하게 채운) 버튼은 "예측 실행" 하나만 유지.
- 탭, 모드 토글, "곡선에서 확인" 같은 보조 액션은 아웃라인 또는 텍스트 버튼으로 낮춘다.

### 숫자 포맷
- Predicted Pt, θ 값, 신뢰도 % 등 화면에 표시되는 모든 숫자는 `Intl.NumberFormat` 등으로 일관되게 반올림·천단위 구분 처리한다.
