# ImperialAX Laminate Forecast — UI 개선 스펙

대상 화면: `Response Forecast` 탭 (다른 탭도 동일 패턴 적용 권장)
현재 URL: https://laminate.imperialax.com/

## 1. 문제 정의

현재 3열 레이아웃(입력 / 라이브 프리뷰 / 결과)에서 오른쪽 결과 컬럼이 예측값 → 신뢰도 → XAI feature 목록 → 디자인 스페이스 산점도 → Case behavior zones까지 한 페이지에 모두 펼쳐져 있어 스크롤이 10회 이상 필요하다. 반면 왼쪽 입력 패널과 가운데 라이브 프리뷰는 짧게 끝나서, 스크롤을 내리면 화면 좌/중앙에 큰 빈 공간이 페이지 절반 가까이 이어진다. 입력값을 바꾸며 결과를 비교하려는 사용자는 입력 패널이 스크롤 밖으로 사라져 반복적으로 위로 스크롤해야 한다. 또한 모든 정보가 같은 시각적 무게로 나열돼 있어 어떤 정보가 핵심이고 어떤 것이 심화 자료인지 구분이 안 된다.

## 2. 개선 방향 (핵심 3가지)

### 2-1. 입력 패널 sticky 고정
왼쪽(또는 결과 패널 기준 좌측) 입력 폼을 `position: sticky; top: <header 높이>;`로 고정한다. 결과가 아무리 길어도 입력값과 "Run forecast" 버튼은 항상 뷰포트 안에 유지되어야 한다.

```css
.forecast-setup-panel {
  position: sticky;
  top: 16px; /* 상단 고정 헤더가 있다면 헤더 높이만큼 조정 */
  align-self: start;
  max-height: calc(100vh - 32px);
  overflow-y: auto; /* 입력 폼 자체가 길어질 경우 대비 */
}
```
부모 그리드 컨테이너는 `align-items: start`가 필요하다 (`align-items: stretch`가 기본값이면 sticky가 동작하지 않음).

### 2-2. 결과 정보의 시각적 위계 재구성
결과 패널을 다음 순서/무게로 재구성한다.

1. **핵심 요약 카드** (가장 크게, 항상 펼쳐짐): 예측 Type, 확률(%), Predicted Pt, Max displacement, Reliability — 지금처럼 숫자 나열이 아니라 3~4개 metric 카드로 그룹화.
2. **곡선 차트** — 접고 펼 수 있게 하되 기본은 펼침 상태 유지 (핵심 결과이므로).
3. **XAI (왜 이 예측인가?)** — 기본 접힘. 클릭 시 feature importance 목록 펼침.
4. **디자인 스페이스 / Case behavior zones / Nearest simulations** — 기본 접힘. 심화 분석을 원하는 사용자만 펼쳐서 봄.

### 2-3. 아코디언(접기/펼치기) 컴포넌트 도입
XAI, 디자인 스페이스, Case behavior zones 섹션을 네이티브 `<details>/<summary>` 또는 별도 토글 컴포넌트로 감싼다. 네이티브 `<details>`를 쓰면 접근성(키보드 포커스, 스크린리더)이 기본 제공되어 우선 권장한다.

```html
<details class="result-section">
  <summary>왜 이 예측인가요? (XAI)</summary>
  <div class="result-section-body">
    <!-- feature importance 리스트 -->
  </div>
</details>
```

화살표 아이콘은 CSS `transform: rotate()`로 열림/닫힘 상태에 따라 회전시켜 상태를 명확히 보여준다.

## 3. 인터랙션 상세

- "Run forecast" 클릭 시 로딩 스피너 표시 → 완료되면 핵심 요약 카드로 자동 스크롤 또는 짧은 하이라이트 애니메이션(예: 배경색 페이드) 적용. 지금은 스크롤 위치가 그대로라 결과 갱신을 사용자가 못 알아챌 수 있음.
- 아코디언은 마지막으로 사용자가 펼친/접은 상태를 세션 동안 기억(로컬 상태)해서, 재실행 시에도 유지.
- 모바일/좁은 화면(≤1024px)에서는 sticky 입력 패널을 상단 고정 대신 일반 흐름으로 전환하고, 3열 그리드를 1열로 스택.

## 4. 참고 목업

레이아웃 컨셉 스크린샷은 대화 중 공유한 위젯 참고 (좌: sticky 입력 패널, 우: 요약 카드 + 아코디언 3개).

## 5. 이번 리디자인 범위 밖, 추가로 검토할 부분

- **Stack Lab 수식 입력 UX**: `±θ₁ / ∓θ₂` 같은 버튼과 수식 문자열 입력이 도메인 전문가에게도 진입장벽이 있음. 버튼에 hover 툴팁/예시 미리보기 추가, 또는 "기본 모드(케이스 드롭다운) / 고급 모드(수식 직접 입력)" 분리 고려.
- **Curve CSV 탭 미검토**: 파일 업로드 UX(드래그앤드롭, 잘못된 형식 에러 메시지, 업로드 진행률)를 별도로 점검 필요.
- **숫자 포맷 일관성**: 화면마다 소수점 자리수·천단위 구분이 다를 수 있음 (`17,190.1` vs `17163.21` 등) — `Intl.NumberFormat` 등으로 통일 권장.
- **Run 버튼 비활성/검증 피드백**: Theta·Panel 치수 입력값이 범위를 벗어나거나 비어있을 때 인라인 에러 메시지 필요. 현재는 버튼을 눌러야 결과가 나오는지 실패하는지 알 수 없음.
- **반응형 테스트**: 3열 그리드가 1280px 이하 뷰포트에서 어떻게 깨지는지 실측 필요 (현재 미확인).
- **다크모드 지원 여부**: 존재한다면 카드/보더 색상이 대비 기준을 만족하는지 점검.
- **Prediction history 카드 활용도**: "Tap a card to reuse its setup"라고 안내는 있으나, 여러 예측을 나란히 비교하는 기능(비교 테이블/오버레이 차트)이 있으면 실사용성이 높아질 것.
