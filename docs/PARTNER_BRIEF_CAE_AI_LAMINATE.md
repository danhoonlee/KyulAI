## 2. 출발점 — PPT가 정의한 사양 `[90초]`

`Final ver2.pptx`의 Double-Double 전이하중 최적화 연구가 이 모델의 사양서다.

**해석 설정**
```
평판 직사각 패널 · 16 ply · ply 두께 0.0075 in · Toray T800/3900S
측면 단순지지, x=0 및 x=a 고정, x=a에서 하중
```

**Case 정의** — 같은 각도라도 두께 방향 배치가 다르면 `D*`가 달라진다
```
Case2:  [[±θ₁]/[±θ₂]]₄
Case3:  [[±θ₁]/[±θ₂]/[∓θ₁]/[∓θ₂]]₂
Case4:  [([±θ₁]/[±θ₂])₂ / ([∓θ₁]/[∓θ₂])₂]
```

**예측 목표는 전이하중 Pt**
비대칭 적층은 B 행렬이 0이 아니어서 막-굽힘 연성이 생기고,
**선형 좌굴해석은 사용 가능 하중을 과대평가한다.**
따라서 모드 형상을 초기 결함으로 씨딩한 비선형 정적해석에서 전이하중을 읽는다.

**PPT 보고 결과**

| | 전이하중 | 준등방성 대비 |
|---|---:|---:|
| Quasi 기준 | 12,344.8 lbs | — |
| Case3 최적 | 15,916.5 lbs | **+28.9%** |

최적 영역 `θ₁ ≈ 44.13°, θ₂ ≈ -49.42°`, 응답면은 **네 모서리 봉우리 + 중앙 저지대**.

> 🗣 *"PPT는 이 최적점을 해석을 돌려서 찾았습니다. 한 건에 20분씩 걸리는 해석을요.
> 저희는 그 과정을 학습시켜서, 해석 없이 같은 판단을 하도록 만드는 게 목표였습니다."*

# 2부 — 질의응답 대비 백업

발표에서 뺀 내용. 질문이 나오면 꺼낸다.

## Q. 455일이라는 건 직렬 기준 아닌가요? 병렬로 돌리면 되잖아요

맞다. **455일은 단일 코어 누적 해석시간**이다. 실제로는 병렬로 돌린다.

| | 소요 |
|---|---:|
| FE 직렬 (1코어) | 455일 |
| FE 100코어 병렬 | **4.6일** |
| **대리모델** | **8.6초** |

병렬화를 최대로 가정해도 **4.6일 대 8.6초**다.
그리고 이건 **Case 1종 · 패널 1종** 기준이다.
Case 3종 × 패널 3종이면 여기에 9를 곱해야 한다.

핵심은 배수가 아니라 **의사결정 주기**다.
설계 검토 회의 중에 "이 조건이면 어떻게 되나요"에 답할 수 있느냐,
아니면 다음 주에 답하느냐의 차이다.

그리고 해석 자원은 무료가 아니다. 대리모델이 후보를 좁혀주면
**같은 해석 자원을 유망한 설계 검증에 집중**할 수 있다.

## Q. 그 20분과 0.4초는 어떻게 측정한 건가요?

- **20분** — 협력사 설명 시점 기준 실제 해석 1건 소요시간
- **0.4초** — API 엔드투엔드 단건 응답. 곡선 1,001점 생성 포함, 실측
- **8.6초** — 181×181 격자 32,761점 일괄 예측 실측
  (피처 생성 8.4초 + 추론 0.2초, 점당 0.26 ms)

일괄 예측이 단건보다 점당 훨씬 빠른 것은 API 오버헤드가 없고
행렬 연산이 한 번에 처리되기 때문이다.

## Q. Type이 뭔가요?

Pt 기준으로 곡선이 좌우로 나뉘며, **양쪽이 선형에 가까울수록 좋은 설계**다.
3-class 분류가 아니라 **bilinear 기술이 얼마나 성립하는가의 등급**이다.

| Type | 곡선 형상 | 전이하중 정의 |
|---|---|---|
| **Type 1** | 명확한 bilinear | 하중 플롯 교점 |
| Type 2 | 전이 이후 휘어짐 | 하중 플롯 교점과 **u3 플롯 교점의 평균** |
| Type 3 | 크게 휨, 피팅 불가 | **u3 플롯 교점** |

## Q. 최대하중은 왜 예측 안 하나요?

변위가 **0.15 in로 고정**된 조건이라 최대하중은 사실상 스트로크 끝점 값이다.
샘플 180건 전수 확인 결과 **180건 모두** 최대값이 곡선 끝에 있었다.
Pt와 나란히 보고하면 같은 결과를 두 번 세는 셈이 된다.

## Q. 어떤 모델을 쓰나요? 왜 그걸 골랐나요?

단일 모델에 의존하지 않기 위해 계열별로 전수 비교했다.

| 계열 | 내용 |
|---|---|
| Tabular | RandomForest, ExtraTrees, HistGB, LightGBM, XGBoost, CatBoost, Ridge, ElasticNet |
| Deep | Plain/Residual/Gated MLP, Stack LSTM, Stack GRU, Stack GNN, Stack GAT |
| 연산자 학습 | DeepONet 계열 |
| 물리 결합 | PINN 인접 구조, Physics-guided MLP |
| 곡선 표현 | PCA curve head |
| 혼합 | Hybrid expert bundle |

→ **Tree / GointMLP / Hybrid Student** 3종으로 수렴. 현재 Tree가 가장 안정적이다.

## Q. 왜 GointMLP는 6×4에서 유독 약한가요?

문제 칸이 **Type 2**다. 트리는 패널 전반에 평평한데(1.15 / 0.97 / 1.10%)
MLP는 6×4에서만 3.6배 나쁘다(8.11% vs 2.26 / 3.62%).

Type 2는 Pt가 **두 교점의 평균**인 구간이다.
매끄러운 신경망은 규칙 전환을 근사하고, 트리는 그 경계를 가로질러 분할한다.

## Q. 패널마다 Pt 정의가 다르다고요?

PPT의 Type 2·3 정의는 **면외 변위(u3) 곡선을 필요로 한다.**

- **6×4** — u3가 있어 PPT의 Type별 정의를 그대로 적용
- **6×8 / 8×8** — u3가 없어 하중 곡선의 꺾임점으로 정의

검증: 저장값을 자체 곡선에서 꺾임점으로 재계산하면
6×8·8×8은 **120/120 완전 일치**, 6×4는 **0/120**(중앙값 27% 차이).

**대응:** 패널 간 Pt 절대값을 직접 비교하지 않고 **지표를 항상 패널별로 분리 보고**한다.
발표 자료의 모든 표가 그 원칙을 따른다.

## Q. Type 라벨은 사람이 다 봤나요?

**아니다.** 6×4의 900건만 사람이 검토했다. 6×8/8×8은 분류기 출력이다.

대신 **Pt를 입력으로 쓰지 않고 곡선 형상만 보는 독립 측정**을 만들어
사람이 검토한 900건으로 캘리브레이션한 뒤 교차 확인했다.

| 패널 | 저장 Type 1 비율 | 독립 측정 |
|---|---:|---:|
| 6×4 | 35.7% | 35.6% |
| 6×8 | 25.2% | 24.0% |

→ **패널이 커질수록 Type 1이 줄어드는 경향은 라벨링 편향이 아니라 실제 물리다.**

## Q. DD 문헌의 라미네이션 파라미터는 안 쓰나요?

**구현해서 검증했고, 개선 없음으로 확인되어 기록해 두었다.**

이유도 규명했다. Tsai-Pagano 형식으로 전개하면
```
A*₁₁ + A*₂₂ + 2A*₆₆ = 2(U₁+U₅)      ← 재료만의 함수
A*₁₂ − A*₆₆         = U₄ − U₅        ← 재료만의 함수
```
**기존 피처가 이미 같은 정보를 담고 있었다.** 재진술은 정보를 더하지 않는다.

## Q. 제품 기능은 뭐가 있나요?

## Q. 참조 논문은?

Vijayachandran & Waas, *Composite Structures* **261** (2021) 113320.
8-ply 대칭 적층을 Legacy Quad `[0/90/±45]s` 대비 최적화해
Case I 최대 +35%, Case II·III 최대 +58% 좌굴하중 개선을 보고.

핵심은 수치가 아니라 이 문장이다.
> *"since the geometry, material and thickness remains the same,
> the total mass of the panel remains the same"*

**무게 증가 없이 각도만 바꿔 얻은 개선이다.**

> ⚠️ 논문의 +35/+58%는 **8-ply 대칭 좌굴하중**, PPT의 +28.9%는 **16-ply DD 전이하중**.
> 서로 다른 연구의 다른 지표이므로 **합산하거나 혼용하면 안 된다.**

# 3부 — 발표 전 확인사항

## 1. 해석 시간 수치 — 출처를 분명히 할 것

슬라이드 1의 비교표는 **해석 1건 20분**을 전제로 계산했다.

| 수치 | 출처 |
|---|---|
| 20분 | **발표자 제공** — 실제 해석 소요시간 |
| 0.4초 | 실측 (API 엔드투엔드, 곡선 포함) |
| 455일 | 32,761 × 20분, **단일 코어 누적** 환산 |
| 8.6초 | 실측 (일괄 예측) |

**455일은 직렬 기준이라는 점을 먼저 말하는 편이 낫다.**
엔지니어는 반드시 병렬화를 떠올리고, 그걸 우리가 먼저 인정하면 신뢰가 올라간다.
100코어 병렬이면 4.6일이고, 그래도 8.6초와 비교가 된다 (2부 첫 문항).

## 2. 말하면 안 되는 것

- ❌ **"Type 라벨 전수 사람 검토"** — 6×4 900건만 해당
- ❌ **"전 패널 통합 Pt MAE"를 단일 지표로 강조** — 패널별 분리가 원칙
- ❌ **논문 수치와 PPT 수치 합산** — 다른 연구의 다른 지표

## 3. 대외 공개 범위 — 확인 완료

| 항목 | 판단 |
|---|---|
| 재료명 (Toray T800/3900S) | ✅ 공개 가능 — 2026-09-21 확인 |
| 성능 수치 (Pt MAE, Type 정확도, 유효 비율) | ✅ 공개 가능 — 2026-09-21 확인 |
| 패널 치수 (6×4 / 6×8 / 8×8) | ✅ 성능 수치가 패널별로 제시되므로 함께 공개 |
| Case 정의 수식 | ✅ 공개 문헌 내용 |
| 참조 논문 인용 | ✅ 공개 논문 |

**한 가지만 남았다 — 경계조건.**
슬라이드 2에 다음 한 줄이 들어 있다.

> `측면 단순지지, x=0 및 x=a 고정, x=a에서 하중`

성능 수치와 달리 이것만은 **따로 분리 가능한 해석 설정 정보**다.
빼도 발표 논지에 영향이 없다 — Pt를 왜 좌굴하중 대신 쓰는지만 남기면 된다.
공개가 곤란하면 그 줄만 지우면 된다.

## 4. 시간 배분

```
1. 표지              30초
2. PPT 사양          90초
3. 진행 경과          2분
4. 물리 피처         90초
5. 검증 체계          2분   ← 여기에 시간을 쓸 것
6. 현재 상태         90초
7. 다음 단계          60초
8. 논의              30초
                  ─────
                   10분
```

**슬라이드 5가 핵심이다.** 성능 수치는 협력사가 검증할 수 없지만,
검증 체계는 들으면 바로 판단할 수 있다.
시간이 밀리면 슬라이드 3과 7을 줄이고 5는 지킨다.
